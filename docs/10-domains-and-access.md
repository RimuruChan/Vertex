# 域、资源归属与协作权限

状态：整体重设计的目标架构，实施进度与验收证据见 [实施计划](plans/2026-09-07-domain-redesign.md)。本文中未打通的能力不能视为已经上线。

## 参考与取舍

- [Hydro 官方项目说明](https://github.com/hydro-dev/Hydro#readme) 将用户身份与独立空间分开：空间内数据隔离，管理员分开配置，并支持用户分组和跨域题目复制。Vertex 借鉴域边界与组授权，不复制其 AGPL 实现。
- [Polygon 官方 API](https://codeforces.github.io/polygon-misc/API) 区分 READ、WRITE、OWNER，区分直接权限与群组继承的有效权限，移除直接授权不等于撤销群组权限。Vertex 同样分别展示授权来源，owner 只能通过专用转让操作改变。
- [Codeforces Groups 的官方介绍](https://codeforces.com/blog/entry/9687?locale=en) 与 [群组功能更新](https://codeforces.com/blog/entry/9905?locale=en) 区分管理者、参与者、旁观者，以及开放、审核、邀请加入方式。它们说明了可见性、成员管理与参赛资格是不同概念。以下是 Vertex 自身的规则，不宣称与参考项目逐项等价。

## 基本模型

```text
站点账号 / 可吊销会话
  ├── 站点管理员：账号治理、域治理、Worker 与系统设置
  └── 域 membership：状态 + 域角色
       ├── 域角色：预置角色与有界权限目录
       ├── group：同域成员集合、组内管理者
       ├── 题目：owner、用户/组协作者、独立出题工作台
       ├── 比赛：owner、编辑协作者、裁判、观察员、参赛资格
       ├── 题单：owner、用户/组协作者、有序同域题目
       └── 提交 / 题解 / 讨论 / 公告：明确域和父资源
```

域是租户及导航边界，不是 DNS 域名，也不等同于一个 group。用户账号在站点唯一，可以加入多个域，在每个域拥有不同的身份。group 不跨域，不自动拥有站点角色。

默认域固定为 `official`，显示名为「官方」。根页面进入该域。它由站点维护，不允许通过普通域接口删除、改 slug 或转为私有。普通域由创建者拥有。域 slug 创建后保持稳定，显示名可改。

域可见性为 `public` 或 `private`；成员加入策略为 `open`、`approval`、`invite`。可见性不等于加入策略：一个公开展示的域仍可以要求审批后才能参与。域成员可为 `active`、`pending`、`invited`、`suspended`；待审核和待接受邀请不授予成员操作能力，停用优先于资源授权。站点封禁优先于一切域权限。

## 权限分层

### 站点与域

站点管理员是维护者，不以伪造域角色实现权限。它可以进行域治理，但读取和修改仍必须定位到正确域，不能绕过作用域条件。

域 owner 是具体账号；普通域必须保留一个有效 owner。转让在单个事务内变更归属和成员角色，目标必须是同域有效成员。不能靠删除成员或修改角色表间接删除 owner。

域预置 `admin`、`author`、`member`、`viewer` 角色，并支持从封闭的权限目录定义域内角色。owner 的治理权限独立于可编辑角色。角色中不能出现 `site.*` 能力，域管理员不能授予站点管理员。

| 能力                        | owner | 域 admin | author | member | viewer |
| --------------------------- | ----- | -------- | ------ | ------ | ------ |
| 查看成员可见内容            | 是    | 是       | 是     | 是     | 是     |
| 提交、发题解和讨论          | 是    | 是       | 是     | 是     | 否     |
| 创建题目、比赛              | 是    | 是       | 是     | 否     | 否     |
| 创建题单                    | 是    | 是       | 是     | 是     | 否     |
| 创建/管理 group、成员与角色 | 是    | 是       | 否     | 否     | 否     |
| 管理全域资源                | 是    | 是       | 否     | 否     | 否     |
| 转让/归档普通域             | 是    | 否       | 否     | 否     | 否     |

这是预置角色的默认权限，授权来源在页面可查看。域角色决定域治理与一般能力；资源 owner 和显式协作者另外授予其资源内的能力。移除「创建题目」能力不等于转让已经拥有的题目。

### 资源 owner 与协作者

题目、比赛、题单具有显式 owner。创建者默认成为 owner；`created_by` 只用于审计，不能兼任可变所有权。

协作者可为域成员或同域 group。题目/题单的协作角色为 `reader`、`editor`。题目的 reader 协作者可以审阅包，公众只能查看已发布题面；editor 可以编辑工作区和构建。题单协作只授权题单本身，不授予引用题目的访问权。删除、转让、改变公开可见性及管理协作者由 owner 或域资源管理者执行。

题单读取在 SQL 中过滤不可见题目，列表计数与详情、个人进度使用同一题目策略。整单替换需要编辑者可见全部已有条目和新条目；否则 `permissions.editItems=false`，后端拒绝替换，避免保存不完整视图时误删隐藏题目。设置与题目编排在详情页分别保存，协作/转让也位于详情。

群组授权按当前有效成员关系计算，不在授权时展开为一批永久用户授权。退出 group 后继承权限立即失效；移除个人授权时，页面必须说明仍可能有 group 授权。组内普通成员不能修改 group 成员关系；组管理者也不能借此获得 owner 专属操作。

访问顺序固定为：有效站点身份 → 域可见性/成员状态 → 资源属于该域 → 资源可见性、状态与有效协作角色 → 用例条件。资源 owner 不得越过域停用和跨域边界。

服务端响应返回有效 `permissions`，UI 用这些能力控制入口；隐藏按钮不是后端授权。更新、发布、转让、授权与提交等关键写入在事务内重新检查权限，不能只相信请求开始时的缓存。

### 比赛

比赛 owner/编辑协作者负责设置与题目编排；裁判负责答疑、评测诊断和比赛内重测；观察员可以看赛务数据但不能操作；选手必须满足参赛资格并报名。它们都不是站点全局角色。

参赛资格可以面向域成员、指定用户或 group。加入 group 不自动产生提交和榜单记录；报名后才是该比赛的参赛者。旁观资格不授予提交权限。

比赛题目使用独立路由，只显示题面、代码和比赛评测反馈，不挂载普通题解/讨论。交流统一进入澄清区：私有提问只对提问者及赛务可见，广播对有比赛访问权的用户可见。封榜、反馈屏蔽和赛前题面保密继续生效。

### 社区内容

题解/讨论始终继承域及父题目权限，作者也不能绕过撤权后的父资源边界。有效作者可编辑已有且仍可访问的内容；域资源管理者、相应资源 owner 可以治理删除，不得冒充作者改写。题解的私有草稿只对作者和域资源管理者可见。归档只读，停用立即失权。发新内容/回复/点赞需要域创建内容能力。

防剧透由当前练习 AC 解锁，比赛 AC 不参与；锁定内容的正文、点赞和讨论一起受限。题解/题目回复均使用同线程约束。前端直接消费资源权限和线程 `canPost`，mock 按独立账号保存点赞状态；比赛普通讨论入口与数据字段不再保留。

公开练习题被用于比赛时，其已有公开题解不会凭空从全站消失。需要保密的新赛题应使用未公开的题目/发布策略；比赛访问权允许在规定时间读取其题面，不允许读取隐藏测试数据、标程或协作设置。

## 数据库与一致性

### 工作副本、候选数据与发布版本

题目的可变材料与面向解题者的数据分开。工作副本保存题面、元信息、程序和测试计划；构建输入在排队时封存，重试不能换成后来编辑的输入。构建成功或上传预制数据只产生候选数据，只有 owner/域资源管理者的显式发布才能原子切换公开题面、限制和数据。

工作副本 revision 与判题材料 data revision 分开：题面、标题和标签等文案变更不强制重建数据；程序、测试计划、限制等影响构建/评测的变更必须重新准备匹配的候选。发布须核对请求所见的工作 revision 与候选版本，拒绝把未确认的新修改或新产物一起发布。发布记录不可变，包含渲染题面、元信息、数据路径/哈希、配置与来源 revision。

练习提交在创建评测 generation 时固定版本；显式重测采用当时的练习发布版本或比赛绑定版本，取消批次恢复原评测版本。比赛题目固定所选版本，排序/保存编排不偷偷升级，新版本需要赛务明确采用。Worker 领取/重领同一 generation 必须得到同一份版本、限制和数据快照，不能在领取时追随最新发布。仍被比赛、提交或判题任务引用的版本与文件不能随题目删除而丢失；跨域复制另建资源及独立文件引用。

继续使用 PostgreSQL / sqlx 和业务领域分包。开发阶段直接维护 init schema，不为重构堆叠临时 migration。

- `domains`：UUID、稳定 slug、显示名、可见性、加入策略、owner、官方标记、状态。
- `domain_roles`：同域 role key、显示名、封闭目录中的权限集合。
- `domain_members`：`(domain_id, user_id)`、role key、状态与审批信息。
- `domain_groups` / `domain_group_members`：组归属、组管理者、成员；使用同域复合外键。
- 题目、比赛、题单、提交、题解、讨论、公告、标签具有明确 `domain_id`；子数据通过其父资源继承域。
- `problem_access`、`contest_access`、`problem_set_access` 使用显式资源外键及用户/组主体，不使用没有外键保护的任意 `resource_type + resource_id`。
- 比赛题目、题单条目、比赛提交、回复父节点等关系以复合外键或同事务验证保证同域；知道另一域的 UUID 也不能绑定。
- 普通 API 不接受客户端指定任意 `domain_id` 来覆盖路由作用域。查询、分页 count、详情、更新、删除和批次都必须带作用域。
- 敏感变更记录域、操作者、动作和目标的审计事件，不记录 JWT、refresh token、签名凭据或完整程序源码。

内部 UUID 不变。公开数字编号已在资源接入阶段改为域内、按资源种类分配：`domain_number_counters`、插入触发器和 `(domain_id, public_id)` 唯一约束保证并发安全。题目从 1000 开始，其他资源从 1 开始；已删除的已提交编号不复用。响应以字符串表示，数字不作为秘密。资源域和公开身份不能通过普通更新移动；跨域复用必须创建新副本。

## 跨域访问与复用

域 A 的私有资源不会进入域 B 的搜索、统计、讨论、题单、榜单或管理列表。公开跨域跳转必须显示来源域；不在当前域页面内混用另一个域的 ID。

比赛/题单只能直接引用同域题目。跨域复用通过明确的复制操作生成目标域新资源、新 owner 和新公开编号。复制需要目标域创建权限，以及源题目包的复制权限；公开题面可读不等于隐藏数据可导出。保留来源与授权说明，复制后的内容和发布状态独立，来源的后续编辑不改变已经复制的比赛数据。不可变文件可以按内容去重，但源资源删除不得破坏仍被引用的副本。

## API 与页面结构

全局接口保留认证、账号和站点治理；资源接口统一到 `/api/domains/{domain}/...`。业务 handler 注册在已解析域的 group 上，通过 typed context 获得作用域。新增跨层接口必须经过领域 service，handler 不直接写数据库。

```text
/d/official
/d/official/problems/1000
/d/official/problem-sets/1
/d/official/contests/42
/d/official/contests/42/problems/A
/d/official/submissions/123
/d/official/editorials/12
/d/official/authoring
/d/official/authoring/1000
/d/official/groups/1
/d/official/settings/members
/d/official/settings/roles
```

域切换保留有意义的栏目，不把上一域的资源编号带到下一域。旧无域页面按官方域解析并规范化，不依赖全站扫描去猜所属域。

列表只负责搜索、筛选、创建和进入详情。题目工作台的固定分区为「概览/设置、题面、程序、测试数据、构建/发布、协作权限」；上传、编辑、删除、转让均在详情内。创建只收集必要信息，成功后直接进入工作台。比赛、题单、group 使用相同的列表/详情模式。

## mock 与验收

mock 与正常模式共用路由、页面、DTO 和能力判断。仅统一设置面板提供账号切换、数据场景和重置。账号是独立身份，域成员、group、owner、比赛角色与报名分别持久化；不得把同一个账号的全局 role 改成 jury 来模拟比赛权限。

默认演示至少有官方域、一个公开训练域和一个私有域，同一账号在不同域有不同权限。支持访客、普通成员、资源 owner、协作者、选手、裁判、观察员、域管理员、站点管理员的关键视角。管理员没有单独的演示入口页。

完成必须有真实 PostgreSQL 的跨域与权限矩阵测试、API/生成契约检查、正常/mock 构建隔离、角色与域切换的浏览器验证，以及 Worker 任务域上下文的集成证据。不能用一组纯函数测试替代数据隔离验收。
