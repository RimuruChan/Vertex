# 出题流程与后端业务接口优化

范围：题面标准结构与紧凑编辑器、程序内多文件导航、批量生成测试、结构化审阅、检查发布操作和丰富演示数据。开发阶段，不增加旧接口兼容分支；保留用户已有内容和私人副本。

设计参考：Polygon 官方测试脚本说明（https://codeforces.com/blog/entry/9034），洛谷题目规范（https://help.luogu.com.cn/rules/academic/problem-standard）。借鉴生成方案、可预览展开、分段题面和样例说明；不直接执行用户输入的 shell 或 Freemarker。

工作项：

- [x] 后端程序聚合保存：校验程序与代码归属、共享代码隔离、一次 CAS。
- [x] 后端生成方案：确定性的参数和种子展开、受限批次、引用校验、预览和原子应用；复用真实 Worker 的生成、校验和答案流程。
- [x] 后端结构化 review：按题面、程序、测试、规则和附件组织语义更改，保留审阅权限和私有副本边界。
- [x] 标准题面结构与编辑辅助，紧凑行高和更多常用组件。
- [x] 程序内代码列表有独立可滚动区域，不依赖顶部挤满的标签。
- [x] 测试数据生成方案管理与执行入口。
- [x] 结构化版本审阅、明确的检查与发布操作，减少折叠层级。
- [x] 代表性完整 mock：多语言、图表/公式/样例、多个程序及辅助代码、生成器与测试分组、历史和检查报告。
- [x] 领域/服务/API 与前端测试；真实后端/Worker 生成验收；亮暗及窄屏 UI 验收。

当前保持 6d5c0a6 为已推送基线。本轮改动先留在工作区，完成后报告实际验证范围。


## 验证记录（2026-09-22）

- 前端测试：54 个文件、238 项通过；正式构建、mock 构建、格式检查通过。
- 出题模块 Go 测试通过；独立 PostgreSQL 数据库 authoring_workflows_test 的仓储与集成测试全部通过，9 项 Ginkgo 集成规格无跳过。
- 真实 Server + Worker 的新流程 E2E 通过：3 组生成数据 + 2 组手工数据，导出 ZIP 的输入/答案字节与预期完全一致。原有工作副本和冻结检查 E2E 也通过。
- API 隐私测试覆盖私人副本/共享版本权限和秘密数据不进入样例预览；服务测试验证秘密输入 blob 根本没有被读取。
- 浏览器验证：生成参数预览 → 保存并开始检查；结构化章节 review；10 文件程序的独立滚动区域和窄屏选择器；中文默认题面、样例联动、22.4px 编辑行高；亮暗主题及 390px 视口无页面横向溢出。
- OpenAPI 和前端客户端重复生成稳定。现有草稿未重置，示例通过显式创建生成。

边界：生成规则支持参数、种子和重复次数，不执行或导入完整 Freemarker/shell 脚本。分组草稿展示当前评测端尚未支持分组计分的发布提示，不伪装成已支持的正式计分能力。mock 检查是交互模拟，真实执行证据来自独立 Worker E2E。
